# Crimson Desert Telemetry 2.2.8

Restores the complete telemetry path for **Crimson Desert Steam build 26423880**
(EXE **1.0.0.3527**, Windows x64) and adds automatic recovery for compatible game
updates. Player/camera data, filtered and all-around lights, Ambient/GI and
per-light physics visibility use the current build's validated reference.

- **Recovery only when needed.** A known executable with matching code guards
  keeps the normal quick startup. When an update changes addresses, CDT waits
  for valid in-game player/camera data before running the full search.
- **Visible progress and validation.** The HUD shows waiting, search progress,
  validation, success or failure. Native code checks the recovered contract
  independently, and success requires fresh requested light/ambient data and
  physics results where applicable. Failed recovery does not repeatedly rescan.
- **Validated address cache.** Subsequent starts can reuse saved addresses after
  rechecking them. No development tools, internet connection, downloaded offsets
  or manual INI edits are needed. The release's one-time diagnostic switch is empty.
- **OpenRGB companion panel.** The optional separate **CrimsonHue 1.0.6** adds
  parallel Hue/OpenRGB output with device selection and placement in a 3D room,
  plus independent OpenRGB light coverage and background controls. CDT hosts the
  panel in its existing renderer; no Hue controller is bundled in this ZIP.

Automatic recovery handles address relocation within the supported engine layout.
Changed layouts, register roles, physics or shader semantics can still require
a mod update. Recovered sessions report `compatibility.mode = recovered`; this
does not declare every future game build tested. Raw light values and the neutral
HTTP/WebSocket APIs remain intact. The health endpoint adds recovery status.

The owner-installed production-code diagnostic completed a full search without
using its cache, recovered all **30 anchors**, passed native validation and
produced fresh light, Ambient and nine-ray visibility data. HTTP and WebSocket
checks passed with no recovery error. This was the diagnostic candidate; the
regular release ZIP was not reinstalled. **86 managed regressions** and the
native recovery/guard tests passed; the earlier complete native suite covered
**42 tests**. This is not a new physical Hue/OpenRGB or HDR-display acceptance test.

Visibility remains a sampled collision estimate: glass, cages and simplified
geometry can disagree with visibly lit surfaces. Unmeasured, stale or failed
results remain `unknown`. The existing budget and freshness rules remain active.

Close the game before installing/updating. Import and activate the complete
**CrimsonDesertTelemetry-v2.2.8-ModManagers.zip**, keeping all six runtime files
from the same package. Requirements remain **.NET 8 ASP.NET Core Runtime x64**
and an x64 ASI loader. CrimsonHue is a separate optional installation and requires
**.NET 8 Desktop Runtime x64**; its OpenRGB output also requires a running local
OpenRGB SDK server and configured Hue bridge/Entertainment area.
