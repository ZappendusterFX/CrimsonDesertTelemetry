# Crimson Desert Telemetry 2.2.5

This release adds the optional in-game panel for **CrimsonHue 1.0.0**, the
separately installed Philips Hue Entertainment companion. CDT still works on
its own. Its existing renderer now draws the Hue mixer as well as the passive
telemetry HUD; the headless Hue controller owns bridge communication, settings
and lighting output. No second graphics-hook set or Hue controller is bundled
in the Telemetry ZIP. Raw light data, HTTP API v1 and schema 1.6 are unchanged.

- **Optional shared Hue panel:** Ctrl+Shift+H opens or hides Lighting, Room,
  Setup and Advanced, with bridge/Entertainment setup, spatial calibration,
  Recommended/Custom controls, presets and diagnostic data. Change the shortcut
  in Hue Setup; `[CrimsonHue] Enabled=0` disables optional discovery.
- **Separate lighting weights:** the matching Hue controller supports Point
  lights (0–200%), Spotlights (0–1000%) and Own lantern (0–100%). Point/spot
  describes geometry, independently of standalone/grouped contributions. Own
  lantern recognition uses a conservative complete-pair signature for build
  25477059; unsupported or ambiguous cases keep the normal type weight.
- **Consistent hiding:** the title-bar X, Hide settings and shortcut hide Hue
  while sync continues. Use Stop to end lighting. Stop and wait for stopped
  status before leaving the game.
- **Input handoff and cursor corrections:** retain the interactive cursor atlas;
  use raw mouse motion with fallback; wait for observed held game presses to
  release before capture; complete panel-owned releases on hiding; suppress the
  duplicate native cursor inside the owned foreground client. If prompted,
  release held buttons/keys. These changes have mocked-input and shared-renderer
  coverage; they do not prove every independently polled game-input route is covered.
- **Room and spatial controls:** ordinary Point / segmented Wall areas,
  per-segment calibration including horizontal washers, and sharper Recommended
  defaults in Hue. Imported placement is retained; changed Entertainment layouts
  require refresh before restarting sync.

Existing all-around engine-light capture, physics-ray metadata, raw and
grouped/smoothed feeds, clear-only feeds, radar, markers, player/camera and
optional local ambient data remain included. No renderer-derived optical light
visibility feature is added in this release.

**Known visibility limit:** the nine-ray test measures collision, not optical
visibility. Dense cages, simplified closed collision hulls and colliding glass
can classify visibly shining lamps as blocked; noncolliding geometry may not
block them. `rendererSelected` does not prove visibility. Clear-only consumers,
including the current Hue consumer, exclude those blocked sources before type
weighting. Increasing a weight cannot recover them. GPU contribution research
is promising but unfinished and is not advertised as solved.

Targets **Crimson Desert patch 2.03.02**, Steam build **25477059**, Windows x64
(EXE `1.0.0.2976`, exact validated hash). Unknown executables remain unsupported.
CDT requires .NET 8 ASP.NET Core Runtime (x64) and an x64 ASI loader. Optional
CrimsonHue 1.0.0 additionally requires .NET 8 Desktop Runtime (x64).

Close the game before installing or updating. Import and activate/deploy the
complete `CrimsonDesertTelemetry-v2.2.5-ModManagers.zip`. Keep all six runtime
files from the same version; DMM may leave the DLL/CFG companions behind when
removing an older package. Preserve useful INI preferences and your ASI loader.
Install the separate CrimsonHue ZIP only if Hue lighting is wanted.
