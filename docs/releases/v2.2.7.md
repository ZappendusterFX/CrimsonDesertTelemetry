# Crimson Desert Telemetry 2.2.7

Fixes visibility-query admission during rapidly changing light effects. Retired
source positions could fill the bounded cache for five seconds and prevent new
current lights from being queried, even when the current scene was well below
the 256-target limit. CDT now makes room by retiring entries no current target uses.

New positions remain `unknown` until their own fresh physics measurement arrives.
Late results cannot revive a removed cache entry. Query budgets, position matching,
500 ms freshness, the raw API and native game hooks are unchanged. This addresses
an older managed-cache defect, not a regression introduced by the game update.

Targets **Crimson Desert patch 2.04.05**, Steam build **26361232**, EXE
**1.0.0.3479**. The exact-build native profile and clean production INI remain the
same as 2.2.6. Research instrumentation remains compiled out.

Synthetic cache-pressure, late-response and existing managed regressions pass.
The exact new package has not been installed or tested in the game. Collision
visibility still differs from optical transmission for cages/glass and other
geometry; genuinely unmeasured, budget-limited and stale results remain unknown.
This does not promise to remove every light fluctuation or preserve an effect
that never obtains a clear measurement.

With the game closed, the owner installs the complete
**CrimsonDesertTelemetry-v2.2.7-ModManagers.zip**. Keep all runtime files from the
same package. Requirements remain .NET 8 ASP.NET Core Runtime x64 and an x64 ASI
loader; CrimsonHue is a separate optional package.
