# Crimson Desert Telemetry 2.2.3

This release makes the optional visibility-filtered light view show only lights
with a fresh `clear` physics result. It also adds a separate filtered API feed
for consumers that need the same rule. The unfiltered light records remain
available with their original RGB and honest visibility metadata.

- With `HideOccluded=1`, the radar and world markers hide `blocked`, `unknown`,
  missing and stale results. A moving light becomes visible again only after a
  new `clear` measurement. The setting remains optional.
- `/v1/lights/visible` over HTTP and WebSocket contains only fresh `clear`
  contributions before grouping or smoothing. A clear-to-unknown transition
  removes the hidden contribution from this feed immediately. Raw and smoothed
  feeds retain the complete captured light data.
- The native HUD evaluates filtered visibility directly from the current
  record, avoiding a temporary copy for every marker while preserving the
  status and freshness rules used by the detail view.

This package targets Crimson Desert patch **2.03.02** on Steam for Windows
(EXE `1.0.0.2976`, Steam build `25477059`, exact validated EXE hash). Unknown
game executables remain unsupported. The sporadic world-entry hang observed
with ReShade remains under investigation.

In the owner's live test of this exact ZIP, global sky RGB was fresh, while
camera-local sky visibility did not publish and the derived local ambient RGB
remained unavailable. This optional field has also been absent in an earlier
release session on the same game patch. Consumers must check its availability;
global sky RGB remains independent of it.

Close the game before importing the complete `ModManagers.zip` in DMM. DMM 3.1.1
has previously left DLL and CFG companions after removal; check the six runtime
files after an upgrade. Preserve a customized INI before replacing the package.
[Installation details](../../README.md).

The earlier private 2.2.2 candidate was quarantined by Microsoft Defender on
the owner's machine. This 2.2.3 ASI passed a local Defender custom scan after
being copied under its deployed filename. A scanner result does not guarantee
acceptance by later signatures or at game launch. Package, offline test and
live results are tracked in the [validation record](v2.2.3-validation.md).
