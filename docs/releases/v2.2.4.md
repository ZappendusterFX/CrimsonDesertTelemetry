# Crimson Desert Telemetry 2.2.4

This release fixes two problems at world entry. Light data, visibility, API
routes, schema 1.6 and INI settings are otherwise unchanged.

- **Camera-local sky visibility no longer stays unavailable for a whole
  session.** Its GPU copy could be recorded during the first loading frame,
  before Telemetry's submission hook existed. If the game never reused that
  command list later, the value never updated. `visibility` in `/v1/ambient` and
  the derived `localEnvironmentAmbientEstimateWorking` then stayed null. 2.2.4
  records this copy only after the hook has observed a submission.
- **More robust sky readback.** A copy that is not submitted within 5 seconds,
  whose fence signal fails, or whose GPU fence does not complete within 5 seconds
  is abandoned and re-armed. A removed graphics device reports the field as
  unavailable instead of a sample. Both fields remain optional and nullable.
- **No extra Direct3D 12 queue at world entry.** Earlier versions created their
  own compute queue at world entry only to find the game's command submission
  function. In one 2.2.3 crash, this call failed shortly after an NVIDIA driver
  error, and the game stopped with `DXGI_ERROR_DEVICE_HUNG`. 2.2.4 takes the
  function from the game's own presentation queue. If HUD, light markers and
  notifications are all disabled, the previous method remains the fallback.
- Corrected texts: F11 (`HideOccluded`) shows only lights with a fresh `clear`
  result, as implemented since 2.2.3. The INI and packaged README described the
  older behaviour.

The owner tested the same native code as a private package: six world entries
with and without ReShade and Crimson Weather were clean. Lights, sky visibility
and the local ambient estimate progressed in both setups. Six clean starts do
not prove that the rare world-entry hang is gone. Please report a recurrence
with the four Telemetry logs.

This package targets Crimson Desert patch **2.03.02** on Steam for Windows
(EXE `1.0.0.2976`, Steam build `25477059`, exact validated EXE hash). Unknown
game executables remain unsupported.

Close the game before importing the complete `ModManagers.zip` in DMM. DMM 2.8.1
and 3.1.1 can leave the two DLL and two CFG companions after removal; check the
six runtime files after an upgrade. Preserve a customized INI before replacing
the package. [Installation details](../../README.md).
