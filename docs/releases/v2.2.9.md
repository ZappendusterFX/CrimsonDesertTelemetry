# Crimson Desert Telemetry 2.2.9

Adds simulation-based acquisition pause and configurable menu lighting with the
separate **CrimsonHue 1.0.7** companion. The current validated reference remains
**Crimson Desert Steam build 26423880**, EXE **1.0.0.3527**, Windows x64.

- **Pause acquisition in menus.** After 500 ms without simulation progress, CDT
  suspends new light, ambient and visibility work and skips managed pose/camera
  sampling. The independent 20 Hz observer keeps running. Resume requires fresh
  captures; old GPU/physics results and smoothing history are discarded.
- **Independent activity API.** `/v1/activity` and `/v1/activity/stream` report
  `running`, `paused` or `unknown`, observer age, acquisition pause and session/epoch
  information. Their schema is **1.0**. Missing or stale observers become unknown;
  normal snapshot routes and light schema 1.6 remain compatible.
- **Editable menu light in the shared HUD.** With CrimsonHue 1.0.7 installed,
  open **Lighting → Menu lighting** to select brightness and color/hex, then
  **Save menu lighting**. **Reset menu lighting** restores warm white at 20%;
  **Gold preset** is an optional choice. Existing settings are preserved. Hue
  and enabled OpenRGB devices use the fixed color during a detected pause and
  blend back over 500 ms once fresh gameplay data returns.
- **OpenRGB cleanup controls.** The shared page adds **Reset OpenRGB settings**
  and **Remove disconnected devices**. Both require stopped sync; cleanup also
  requires a fresh device read. Reset keeps the SDK port and Hue settings while
  disabling OpenRGB, restoring its defaults and moving current devices to the
  default front position. Cleanup preserves connected placements and output settings.
- **Quiet pause and resume.** Intentional pauses and pending post-resume captures
  no longer appear as light-reader failures. Closing a menu does not repeat
  “Telemetry is ready.” First startup, actual scene loads, genuine errors and
  compatibility recovery keep their notifications.

Pause detection measures simulation progress, not individual menu IDs. Other
simulation stalls can trigger it. The reported controller-only Skills-menu
stutter and rapid hover sounds remain unresolved; this release is not a fix for
that issue. Automatic hiding of every telemetry view in every menu is not added.

The production template enables `[Pause] Enabled=1`; use `0` to disable the policy.
The monitor-only diagnostic remains off and research instrumentation is excluded.
Guarded automatic recovery from 2.2.8 remains available for compatible address
relocations; changed engine layouts or semantics can still require a mod update.

The tick signal was checked across gameplay → Skills → gameplay. Owner-installed
menu candidates also exposed active pause and fixed companion output. Regression
tests cover observer freshness, pause/resume capture boundaries, physics-result
expiry, and the ready-notice transition including real failures. These checks do
not establish a Skills-stutter fix or acceptance on every controller/GPU/display.
The production release passed **94 managed tests and all 45 native tests**, the
exact packaged companion's shared-HUD smokes and folder/ZIP validation. See the
[validation record](https://github.com/ZappendusterFX/CrimsonDesertTelemetry/blob/v2.2.9/docs/releases/v2.2.9-validation.md).

Close the game before updating. Import and deploy the complete
**CrimsonDesertTelemetry-v2.2.9-ModManagers.zip**, keeping all six runtime files
from the same package. Requirements remain **.NET 8 ASP.NET Core Runtime x64**
and an x64 ASI loader. CrimsonHue is optional and downloaded separately; it needs
**.NET 8 Desktop Runtime x64**. OpenRGB additionally needs its local SDK server and
the companion's configured Hue bridge/Entertainment area.
